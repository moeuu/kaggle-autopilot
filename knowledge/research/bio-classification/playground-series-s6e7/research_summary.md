## Ranked shortlist

### 1. GPU GBDT diverse core — primary foundation

**Leak-free features/encodings:** retain all 13 raw predictors; add per-column missing flags, total missing count, the sleep/stress/activity missingness regime, safe physiological/activity ratios, bounded logs, threshold distances, ordinal views, and a few categorical crosses. CatBoost receives raw string categoricals with `__MISSING__`. XGBoost receives medians, clips, 64-bin quantiles, frequencies, and smoothed multiclass target encodings fitted inside each outer training fold; outer-train target encodings are generated by four-way inner cross-fitting.

**Models and chosen settings:** CatBoost GPU with 6,000 trees, learning rate 0.035, depth 8, `l2_leaf_reg=8`, `border_count=254`, Bayesian bootstrap, and exponentiated class weights at 0.85. XGBoost CUDA histogram with 6,000 trees, learning rate 0.025, depth 7, `min_child_weight=8`, subsample 0.85, column sample 0.90, `reg_lambda=6`, and 250-round early stopping. Run five folds, one full seed.

**Expected runtime/memory:** about 180–300 minutes, generally 4–10 GB VRAM when families and folds are sequential. **Leakage risk:** medium if target encoding is implemented incorrectly; low after strict inner cross-fitting and fit/apply transformers. **Fallback:** lower CatBoost depth/borders, use XGBoost CPU `hist`, or use LightGBM on the identical encoded matrix. Official XGBoost and CatBoost sources support the chosen GPU/categorical families. ([XGBoost Documentation][1])

### 2. RealMLP-TD-S diversifier — preferred neural member

**Leak-free features/encodings:** fold-fitted robust scaling, smooth clipping, explicit missing indicators, train-only category vocabularies with missing/unknown codes, and the deterministic features above. Do not share a scaler, vocabulary, clipping bound, or target statistic across validation folds.

**Model and chosen settings:** self-contained PyTorch RealMLP-TD-S-compatible network with hidden widths 512/512/256, dropout 0.10, batch 4,096, learning rate 0.001, weight decay 0.0001, label smoothing 0.01, class-weight exponent 0.75, up to 120 epochs, 15-epoch early stopping, gradient norm 1.0, and three full folds from seed 42.

**Expected runtime/memory:** about 150–300 minutes, 5–9 GB VRAM. **Leakage risk:** low if preprocessing is instantiated per fold; calibration drift rather than leakage is the larger concern. **Fallback:** embed the compact MIT-licensed standalone RealMLP preprocessing/model logic in `kernel.py`; if AMP is unstable, use float32 and batch 2,048 or 1,024. The paper and standalone repository support RealMLP as a strong, practical complement to GBDTs. ([arXiv][2])

### 3. Local TabPFN-3 — optional high-ceiling promotion candidate

**Leak-free features/encodings:** aligned raw predictors plus a compact deterministic feature set; train-fold category vocabularies only; no global target encoding, no public prediction files, and no manual prior division when `balance_probabilities` is disabled.

**Model and chosen settings:** local TabPFN-3 with four estimators, CUDA, low-memory mode when supported, three validation folds, seed 42, 16,384-row test chunks, and a 10.5 GB soft VRAM ceiling. Retry with 8,192/4,096-row chunks and two estimators before skipping.

**Expected runtime/memory:** 180–420 minutes if the preflight succeeds; memory is implementation/version dependent. **Leakage risk:** low for honest OOF inference, but asset/license and reproducibility risk are high. **Fallback:** skip with a machine-readable reason when the package, accepted license, revision-pinned checkpoint, or checksum is missing; never call a hosted API. TabPFN-3 has relevant large-row evidence, but that evidence uses substantially larger hardware, so this remains a gated candidate. ([arXiv][3])

### 4. Cross-fitted calibrated blend + boundary refiner — final selection layer

**Leak-free features/encodings:** aligned OOF probabilities from promoted base models; log probabilities, class margins, entropy, disagreement, and low-cardinality raw/missingness features. All weight, bias, and refiner tuning occurs in five meta-folds; the reported meta score is produced only on held-out meta-fold rows.

**Models and chosen settings:** compare best single, arithmetic blend, geometric blend, and bounded class-logit calibration. Search nonnegative weights with step schedule 0.20→0.10→0.05→0.02→0.01; tune class biases inside ±0.70 with L2 0.002. The optional XGBoost refiner uses 900 trees, learning rate 0.03, depth 4, and only affects rows with base margin below 0.30 at blend alpha 0.35.

**Expected runtime/memory:** 40–100 minutes, usually below 6 GB. **Leakage risk:** high if the same OOF rows are used both to tune and report; controlled by nested meta-folds. **Fallback:** retain the best single/base blend unless gain is at least 0.00015, at least four meta-folds are non-negative, and no class recall falls more than 0.002. Bounded logit adjustment is aligned with long-tailed classification, but double prior correction is forbidden. ([arXiv][5])

## Promotion order

Run a real two-fold fast tree path first to validate I/O, metric, artifacts, and CUDA. Complete the five-fold tree core next. Add RealMLP if the watchdog remains healthy; add TabPFN-3 only after checkpoint/license preflight. Build the cross-fitted meta layer from whatever honest OOF members completed. The expected final is the calibrated cross-family blend, with the refiner accepted only under the stated recall and fold-consistency guards. Public-submission ensembles and hardcoded corrections are not shortlist candidates.
